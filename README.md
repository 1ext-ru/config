# config — публичная конфигурация 1ext.ru

Единственный файл конфигурации, который читают информационные базы с фреймворком ЕХТ:
из него берутся адреса сервисов — шины данных, серверов обновлений и MCP-моста.

## Как это работает

1. В коде расширения захардкожены **загрузочные** адреса этого файла (по порядку):
   - основной — `https://1ext.ru/config/config.json` (свой домен, без зависимости от блокировок);
   - резервный — `https://raw.githubusercontent.com/1ext-ru/config/main/config.json`
     (нужен ровно на случай, когда домен сменился или недоступен).
2. Прочитанные значения **кэшируются в настройках базы** (`ЕХТ_Настройки`), поэтому файл дёргается
   не на каждый вызов, а при отсутствии значения или по явному запросу обновления.

Репозиторий — источник истины; на `1ext.ru/config/` содержимое попадает синхронизацией.

## Формат

```json
{
    "format": "26.07.25.1",
    "settings": {
        "ESB": ["https://1ext.ru/esb/hs/1ext.esb/"],
        "UPDATE": ["https://1ext.ru"],
        "MCP": ["wss://mcp.1ext.ru"]
    }
}
```

| Ключ | Тип | Назначение |
|---|---|---|
| `format` | Строка | версия схемы по схеме ЕХТ `ГГ.ММ.ДД.НомерСборки`; бампать при добавлении ключей |
| `ESB` | Массив строк | HTTP-сервис шины данных (`ЕХТ_ШинаДанных`) |
| `UPDATE` | Массив строк | серверы обновлений расширений (`ЕХТ_ОбновлениеРасширений`) |
| `MCP` | Массив строк | MCP-мост для 1С, схема `wss://` (`ЕХТ_МСР`) |

Значения — массивы: первый адрес основной, остальные резервные. Код перебирает их по порядку.

## Правило совместимости: ключи только ДОБАВЛЯТЬ

Файл читают одновременно все версии расширения, которые умеют брать конфигурацию отсюда.
Поэтому существующие ключи не переименовывать и не удалять — только добавлять новые, бампая `format`.
Менять **значения** можно свободно: в этом и смысл — переезд сервиса не требует обновления расширений
у клиентов.

## Что здесь НЕ хранится

**Секреты.** Репозиторий и `1ext.ru/config/` публичны. Логины, пароли и токены (в том числе Basic
для MCP-моста) живут только в настройках конкретной базы. Здесь — исключительно «куда подключаться»,
но не «чем доказать право».

## Предыстория и совместимость со старыми базами

Раньше конфигурация лежала на Bitbucket (`bitbucket.org/akaygorodov/1ext.ru`): `config.json` с адресом
шины и отдельный `servers.lst` со списком серверов обновлений. Переезд вызван тем, что тот workspace
превысил лимит 1 ГБ и переведён в read-only — менять конфигурацию там больше нельзя.

**Ранее установленные базы продолжают читать Bitbucket** (адреса захардкожены в их версии расширения),
поэтому здесь нет ни `servers.lst`, ни старых русских ключей `Настройки.АдресСервисаШиныДанных`:
для них ничего не изменилось, а новый формат нужен только новым версиям.

## Резервный адрес и ветка

Резервный URL завязан на ветку `main` — **переименовывать её нельзя**, иначе у установленных баз
сломается запасной источник. Отдача `raw.githubusercontent.com` кэшируется CDN около пяти минут:
для конфигурации это несущественно, но мгновенного распространения правки там не будет.
